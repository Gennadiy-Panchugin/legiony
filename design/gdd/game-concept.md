# Game Concept: Легионы (рабочее название)

*Created: 2026-10-01*
*Status: Draft*

---

## Elevator Pitch

> Мобильная стратегия, где вы направляете потоки легионеров, лучников и конницы
> между зданиями, чтобы захватить поле боя — и шаг за шагом завоевать античный
> регион на карте кампании.

## Core Fantasy

Вы — полководец античного мира, который побеждает не числом, а умом: читаете
поле боя, видите, где враг оголил фланг, и одним движением пальца разворачиваете
реку конницы туда, где её не ждут. Между битвами вы ведёте войну целиком —
выбираете, какую провинцию брать, и развиваете технологии своей державы.

---

## Unique Hook

Как Tower War, **и при этом** здания производят разные типы войск (пехота,
лучники, конница) с контрами «камень-ножницы-бумага», а потоки сталкиваются на
дорогах — так что захват здания меняет состав вашей армии, а каждый бой
продвигает фронт на исторической карте кампании.

## Player Experience Analysis (MDA Framework)

### Target Aesthetics (What the player FEELS)

| Aesthetic | Priority | How We Deliver It |
| ---- | ---- | ---- |
| **Challenge** (obstacle course, mastery) | 1 | Тактические контры типов войск, хитрый ИИ, растущая сложность карт |
| **Fantasy** (make-believe, role-playing) | 2 | Античный полководец, легионы, завоевание региона |
| **Sensation** (sensory pleasure) | 3 | Видимые реки юнитов, зрелищные столкновения, перекрашивание зданий |
| **Discovery** (exploration, secrets) | 4 | Новые технологии и юниты, новые провинции на карте |
| **Narrative** (drama, story arc) | 5 | Лёгкая — история завоевания через продвижение фронта |
| **Expression** (self-expression, creativity) | 6 | Выбор пути по дереву технологий и порядка провинций |
| **Submission** (relaxation, comfort zone) | N/A | — |
| **Fellowship** (social connection) | N/A | PvP вне объёма этой версии |

### Key Dynamics (Emergent player behaviors)

- Игроки будут разведывать состав вражеских зданий и отвечать контр-типом.
- Игроки будут делать ложные атаки: тянуть вражеский поток на одну точку и бить другую.
- Игроки будут охотиться за ключевыми зданиями (например, конюшней), чтобы лишить врага типа войск.
- Игроки будут переигрывать проигранные бои, потому что видят свою ошибку.

### Core Mechanics (Systems we build)

1. Потоки по линиям: проведённая линия от здания к цели непрерывно отправляет войска, пока её не снимут.
2. Типы зданий → типы войск с контрами (пехота > конница > лучники > пехота).
3. Столкновение потоков на дорогах и захват зданий.
4. ИИ противника, который распределяет потоки и реагирует на угрозы.
5. Карта кампании с провинциями и деревом технологий между боями (post-MVP).

## Player Motivation Profile

### Primary Psychological Needs Served

| Need | How This Game Satisfies It | Strength |
| ---- | ---- | ---- |
| **Autonomy** (freedom, meaningful choice) | Как распределить потоки, какую провинцию брать, какую технологию открыть | Core |
| **Competence** (mastery, skill growth) | Победа решается чтением поля, а не прокачкой; видимый рост мастерства | Core |
| **Relatedness** (connection, belonging) | Фантазия полководца; возможно позже — генералы/герои | Minimal |

### Player Type Appeal (Bartle Taxonomy)

- [x] **Achievers** (goal completion, collection, progression) — How: захват провинций, открытие технологий, завершение региона
- [x] **Explorers** (discovery, understanding systems, finding secrets) — How: понимание контр и синергий типов войск
- [ ] **Socializers** (relationships, cooperation, community) — How: вне объёма
- [x] **Killers/Competitors** (domination, PvP, leaderboards) — How: доминирование над ИИ; PvP — будущее расширение

### Flow State Design

- **Onboarding curve**: первая карта — одна линия, один тип войск, одно вражеское здание; каждая следующая добавляет по одному элементу (второй тип войск, нейтральные здания, контры).
- **Difficulty scaling**: больше вражеских зданий, умнее ИИ, неудобная стартовая позиция; позже — новые типы войск через технологии.
- **Feedback clarity**: цвет зданий показывает баланс сил в реальном времени; при столкновении потоков видно, какой тип выигрывает.
- **Recovery from failure**: бой 2–3 минуты, мгновенный рестарт — поражение обучает, а не наказывает.

## Core Loop

### Moment-to-Moment (30 seconds)

Провести линию от своего здания к цели — по ней течёт поток солдат, тип которых
задан зданием. Встречные потоки сталкиваются на дороге; побеждает численность и
правильный тип. Снять линию, перебросить поток, ударить туда, где враг оголился.

### Short-Term (5-15 minutes)

Один бой (2–3 мин): захватить все вражеские здания. Решения — распылиться или
давить одну точку, каким типом закрыть брешь, какие здания брать первыми.

### Session-Level (30-120 minutes)

На мобильной платформе — 15–30 мин: 3–6 боёв на карте кампании. Выбрал соседнюю
провинцию → бой → захватил → получил ресурсы → открыл технологию. Естественная
точка остановки — захват провинции.

### Long-Term Progression

Дерево технологий: новые здания и юниты, улучшения производства и обороны.
Цель — захватить весь регион. Позже — новые регионы.

### Retention Hooks

- **Curiosity**: какие юниты откроет следующая технология; что за провинцией на границе
- **Investment**: продвинутый фронт и открытые технологии
- **Social**: вне объёма этой версии
- **Mastery**: переиграть трудную карту, найти лучшую тактику против конкретного ИИ

## Game Pillars

### Pillar 1: Перехитрить, а не перекачать
Бой выигрывается решениями, а не цифрами.

*Design test*: Если выбираем между технологией «+20% урона» и технологией, дающей новую тактическую возможность, — выбираем второе.

### Pillar 2: Одна линия — один приказ
Все действия в бою сводятся к «провести / снять линию».

*Design test*: Если фича требует новой кнопки или жеста — встраиваем её в линии или выкидываем.

### Pillar 3: Масса, которую видно
Армия — это толпа живых юнитов на экране, а не число на здании.

*Design test*: Если выбираем между абстрактным счётчиком и видимыми солдатами — солдаты. (Осознанный конфликт с производительностью на мобильных.)

### Pillar 4: Каждая победа двигает фронт
Бой имеет последствия на карте кампании.

*Design test*: Если контент не влияет на кампанию — ему не место в этой версии.

*Напряжение*: Pillar 1 ↔ Pillar 4 — прогрессия между боями не должна решать исход боя заранее.

### Anti-Pillars (What This Game Is NOT)

- **NOT микроконтроль отдельных юнитов**: ломает Pillar 2 и мобильное управление.
- **NOT технологии, которые выигрывают бой заранее**: ломает Pillar 1.
- **NOT PvP, лайв-опс и сетевая игра (в этой версии)**: фокус на кампании против ИИ; сеть многократно увеличивает объём.
- **NOT база и призыв в MVP**: прогрессия только через дерево технологий; можно вернуть позже, если ядро сработает.

## Visual Identity Anchor

*Черновик — ревью art-director (AD-CONCEPT-VISUAL) пропущено в режиме Lean; уточняется в `/art-bible`.*

- **Направление**: «Читаемая масса»
- **Визуальное правило**: цвет фракции считывается раньше формы — поток войск виден как река даже на маленьком экране.
- **Принципы**:
  1. *Силуэт типа войск* — пехота, лучники, конница различимы по силуэту в размере 16–24 px. Тест: если тип юнита неотличим на скриншоте с телефона — упростить форму.
  2. *Здание = функция* — тип здания понятен с одного взгляда (казарма / стрельбище / конюшня). Тест: если игрок спрашивает «что это за здание» — переделать.
  3. *Чистое поле* — фон приглушён, яркость отдана фракциям и потокам. Тест: декор никогда не ярче юнитов.
- **Цветовая философия**: насыщенные контрастные цвета фракций (например, римский красный против варварского синего) на приглушённом земляном фоне; нейтральные здания — серые.

## Risks and Open Questions

### Design Risks
- «Камень-ножницы-бумага» может стать очевидным: если всегда ясно, чем ответить, хитрости нет.
- Снежный ком: ранее лидерство может делать исход боя предрешённым.
- Прогрессия между боями может обесценить мастерство (конфликт Pillar 1 ↔ 4).

### Technical Risks
- Производительность при массе юнитов на слабых телефонах.
- Качество ИИ: хитрый, но не нечестный.
- Первая игра автора — кривая обучения Unity.

### Market Risks
- Жанр захвата зданий насыщен простыми клонами; отличие должно быть видно на первом скриншоте.
- Монетизация не определена.

### Scope Risks
- Полное видение (база, призыв, регионы, PvP, лайв-опс) многократно превышает срок «недели».
- Карта кампании может съесть время до того, как бой станет интересным.

### Open Questions
- Интересны ли контры типов войск в потоковом бою? → `/prototype` боя.
- Как считать столкновение потоков разных типов (множитель урона? прямое уничтожение?) → прототип + `/design-system`.
- Производят ли здания войска бесконечно или есть лимит вместимости? → прототип.
- Монетизация (premium vs F2P) → решить до Alpha.

## MVP Definition

**Core hypothesis**: Бой потоками с тремя типами войск даёт ощущение «я перехитрил противника» и вызывает желание переиграть.

**Required for MVP**:
1. Бой против ИИ: линии-потоки, захват зданий, победа при захвате всех вражеских зданий
2. Три типа зданий → три типа войск с контрами (пехота > конница > лучники > пехота)
3. Столкновение потоков на дорогах
4. Нейтральные здания для захвата
5. 3–5 карт с нарастающей сложностью

**Explicitly NOT in MVP** (defer to later):
- Карта кампании и дерево технологий
- База, призыв
- PvP, лайв-опс, монетизация
- Дополнительные регионы

### Scope Tiers (if budget/time shrinks)

| Tier | Content | Features | Timeline |
| ---- | ---- | ---- | ---- |
| **MVP** | 3–5 карт | Только бой | 2–3 недели |
| **Vertical Slice** | 1 регион, 5–7 провинций | Бой + карта кампании + ~8 технологий | +3–5 недель |
| **Alpha** | 1 полный регион (~20 провинций), новые юниты | Всё ядро, черновой арт | +2–4 месяца |
| **Full Vision** | Несколько регионов (восток, пустыня, арктика) | + база, призыв, PvP, лайв-опс | 12–24+ месяцев |
