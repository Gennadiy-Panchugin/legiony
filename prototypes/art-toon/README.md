# art-toon — мультяшный бой «Легионов» (HTML-прототип)

> PROTOTYPE - NOT FOR PRODUCTION. Одноразовый код; в Unity не переносится напрямую, а переписывается по стандартам продакшена.

## Гипотеза

Мобильный портретный тактический бой в мультяшном 2D (экран 540×960): до четырёх генералов с отрядами, время замедляется при выборе отряда, приказы классов, бусты из запаса, захват точек, оборона от волн, засады и ловушки. Проверялось, может ли такой бой нести боевую часть игры, и можно ли собрать всё в один HTML-файл.

## Как запустить

- Страницы боя собираются в `toonwar/`: `node city-gen.js && node gen.js && node tibur-gen.js && node army-gen.js`.
- В игру они встраиваются из `../html-archive`: `node embed-war.js` (на выходе `legiony.html`).
- Отдельные страницы (`citywar.html`, `war.html`, `army.html`, `tibur-war.html`) открываются напрямую, окно названия задаёт режим (`legwar:<город>`, `legwar:rebel:<город>:clear:dusk`, `legwar:patrol:…`, `legwar:arena:…`).
- Арты листов: `toon2d/` (`*.html`), персонажи и звук: `castle/`.

## Что получилось к моменту закрытия

Последний коммит `967cce6`, артефакт версии 149, Android 0.5.

- Бои: захват пяти городов Лация, Тибур с туннелем, гладиаторская арена с волнами и погодой, мятеж на картах городов, десант на Сардинию, генерируемый дозор.
- Интерфейс: лоток бустов, полоса приказов, окно «Сдаться», кнопка волны, тутор в бою, на экране подготовки и в казарме.
- Механики: бусты (Клич, Щиты, Резерв, Строители), носимый таран, конница не бьёт по крутым буграм, горящие постройки в мятеже, засады и ловушки, лазарет вместо палаток.

## Что важно знать, если к этому вернуться

- Баланс боёв, бустов, мятежа и тарана проверялся только простым ботом и симуляцией, живого плейтеста по ним не было.
- Страницы собираются цепочкой скриптов (`city-gen.js`, `tibur-gen.js`, `gen.js`, `army-gen.js`) и правками по тексту; затем `embed-war.js` вшивает всё в `legiony.html` (около 1,2 МБ) такими же правками. Любая правка исходника ломает хрупкие места, это затрудняло изменения.
- Причина закрытия (со слов заказчика, 2026-10-07): слишком сложно для мобильной игры; не затягивает сразу и нет желания вернуться; избыток механик; непонятно, как монетизировать. Это вывод по концепции, а не по багам: баланса и технических проблем среди причин нет.

## Находки для дизайна (из хода работы, не вердикт)

- Замедление времени при выборе отряда и приказы классов читаются игроками; главная трудность была в интерфейсе, а не в правилах (много итераций правок размеров, подписей и расположения).
- Рабочие механики стоит переносить как идеи, а не код: носимый объект с дебафом, цели захвата, которые враг жжёт первыми, лечение в одной точке, случайные стороны появления волн, обучение с затемнением и рукой.
- Урок для следующего прототипа: механик было слишком много (бусты, приказы классов, таран, ловушки, засады, мятеж, дозор, арена). Начинать стоит с одной механики, которая цепляет за первую минуту, и с понятной причины вернуться в игру; монетизацию продумывать вместе с ядром, а не после.
